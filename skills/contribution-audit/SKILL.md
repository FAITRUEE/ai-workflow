# 내 기여만 가려내 문서로 남기기

팀 프로젝트를 서류에 쓰면 가장 흔한 실수가 **팀 결과를 내 것처럼 쓰는 것**이다.
프로젝트 13개를 이 방식으로 정리했고, 면접에서 "그거 본인이 한 거예요?"에 근거로 답할 수 있게 됐다.

## 1. 근거부터 모은다

| 근거 | 명령 · 위치 |
|---|---|
| 저장소별 내 커밋 수 · 전체 | `git shortlog -sne --all` |
| 파일별 최종 코드 중 내 줄 | `git blame --line-porcelain <파일> \| grep '^author ' \| sort \| uniq -c` |
| 내가 연 · 병합한 PR | `gh pr list -R <조직/저장소> --author @me --state merged --limit 200` |
| 기획 · 설계 문서 | 노션 · docs 폴더 — 작성자 · 변경 이력 |
| 발표 자료 · 보고서 | 수치의 출처(어느 실험 · 어느 조건) |
| 프로젝트 CLAUDE.md · 작업 기록 | 당시 결정과 틀렸던 것 |

- **최종 코드 기준 줄 수**와 **커밋 수**를 둘 다 본다. 초반에 만들었다가 팀원 코드로 대체된 것은 "내가 썼지만 남아 있지 않음"으로 따로 적는다.
- 내 계정이 아닌 커밋(공용 계정 · 페어 작업)은 사용자에게 물어서 정한다.

## 2. 문서 틀

```
# NN. <프로젝트> — <한 줄 정의> (상세 문서)
> 목적 · 분석한 근거 · 작성일

## 링크
## 0. 한눈에 보기        — 기간 · 팀 · 내 역할 · 결과 · 기술 · 기여 근거(PR · 커밋 수)
### ⚠️ 서류에 쓸 때 지킬 범위   — 팀원 몫 · 단정 금지 · 효과 주장 금지 · AI 도구 비중
## 1. 전체 구조 (담당 열 포함)
## 2~N. 내가 한 부분 — 문제 → 한 일 → 결과(수치와 조건)
## 팀원 몫 (참고용, 내 성과로 쓰지 말 것)
## 한계 (스스로 정리한 것)
## 예상 면접 질문
## [확인 필요] — 본인에게 물어볼 것
```

## 3. 지킬 것

- **수치는 조건과 함께.** "F1 0.640"이 아니라 "같은 평가 묶음 · 규칙과 차이 구간이 0을 포함"까지. 비교 대상이 없으면 "더 좋다"고 쓰지 않는다.
- **목표치와 잰 값을 구분한다.** "1초 이내로 만들었다"(잰 값)와 "1초 이내를 목표로 설계"(목표)는 다르다.
- **팀 결과는 주어를 '팀'으로.** 내가 연결만 한 팀원 모델은 "연결은 본인"으로만.
- **AI 도구 비중이 크면 그렇게 적고**, 면접에서 직접 설명해야 할 핵심 로직을 따로 표시한다.
- 근거를 못 찾은 것은 지어내지 않고 `[확인 필요]`에 질문으로 남긴다.
- 서류에 옮길 때는 이 문서의 "지킬 범위"부터 읽는다.
