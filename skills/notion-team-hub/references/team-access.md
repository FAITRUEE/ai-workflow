# 팀원이 Claude로 이 노션을 읽게 하기

2026-10-27 머신러닝 프로젝트에서 실제로 깔아 본 절차. 결론부터: **게스트는 OAuth 방식으로 못 붙는다.
내부 통합 토큰을 써야 한다.**

## 왜 토큰이어야 하나

노션 공식 문서(developers.notion.com/guides/mcp)에 "Only workspace members can connect Notion MCP"라고
적혀 있다. 게스트가 연결을 시도하면 인증이 거부된다. **플랜을 올려도 안 되는 멤버십 규칙**이다.

멤버로 올리면 각자 붙을 수 있지만 무료 플랜은 멤버 2명 이상이면 블록 수 제한이 걸리고,
Plus는 멤버당 월 ₩14,000이다. 교육 무료 Plus는 1인 워크스페이스 한정이라 팀에는 못 쓴다.

내부 통합 토큰은 사람이 아니라 **봇의 권한**이라 멤버십과 무관하다. 토큰 받은 사람은
게스트든 계정이 없든 통합에 연결된 페이지를 읽고 쓴다.

| | OAuth (호스티드 MCP) | 내부 통합 토큰 |
|---|---|---|
| 게스트 | ❌ | ⭕ |
| 보이는 범위 | 그 사람 권한대로 | 통합에 연결된 페이지 |
| 누가 만드나 | 각자 | 워크스페이스 소유자만 (무료 플랜은 소유자 고정) |

## 절차 (소유자가 한다)

1. `notion.so/profile/integrations` → ＋ 새 API 통합
   - 이름은 **팀/조직 이름**으로. 이 이름이 노션 편집 기록에 찍힌다.
   - 연결된 워크스페이스를 반드시 확인한다. 다른 사람 워크스페이스가 목록에 같이 뜬다.
2. 권한은 **콘텐츠 읽기 · 업데이트 · 삽입** 세 개.
   - 댓글은 안 쓰면 끈다.
   - **사용자 정보 읽기**는 선택이다. 켜면 담당자(people) 속성을 Claude가 지정할 수 있지만,
     토큰 가진 사람이 `/v1/users`로 팀원 이메일을 조회할 수 있다. 트레이드오프를 사용자에게 말하고 고르게 한다.
3. **「프로젝트 홈」 한 곳만 연결한다.** 하위 문서·DB는 상속된다.
   - 페이지 ··· → 연결(Connections) → 통합 선택, 또는 통합 설정의 액세스(Access) 탭.
   - **이 단계를 빼먹으면 토큰은 멀쩡한데 아무것도 안 읽힌다.** `claude mcp list`에는 ✓ Connected로
     떠서 제일 헷갈린다. 반드시 아래 검증을 돌린다.
4. `scripts/verify_notion_integration.py`로 확인한다.
5. 토큰은 DM으로 배포한다. 공개 채널에 평문으로 올리면 나중에 채널을 나간 사람도 계속 쓴다.
6. 팀원은 각자:
   - 윈도우 `claude mcp add notion --scope user --env NOTION_TOKEN=받은토큰 -- cmd /c npx -y @notionhq/notion-mcp-server`
   - 맥 `claude mcp add notion --scope user --env NOTION_TOKEN=받은토큰 -- npx -y @notionhq/notion-mcp-server`
7. **프로젝트가 끝나면 통합을 삭제한다.** 토큰 회수가 따로 없어서 그게 유일한 차단 수단이다.

## 검증

```bash
python <skill>/scripts/verify_notion_integration.py <토큰파일경로> [홈페이지ID]
```

토큰은 채팅에 붙이게 하지 말고 파일에 저장하게 한다. 저장 위치는 **스크래치패드**(세션 임시 폴더).
프로젝트 폴더가 git 저장소 안에 있으면 토큰 파일이 커밋될 수 있다.

쓰기까지 확인하려면 `--write <할일보드DB_ID>`를 붙인다. 테스트 카드를 만들었다 바로 휴지통에 넣는다.
실제로 보드에 카드가 잠깐 생기는 일이라 **사용자에게 먼저 물어보고** 돌린다.

## 알려줄 것

- 편집 이력이 전부 통합 이름으로 찍혀서 **누가 썼는지 구분이 안 된다.**
  일지·실험 기록의 담당 칸은 본인 이름으로 직접 채우라고 공지에 넣는다.
- 통합에 연결한 페이지는 토큰 가진 전원이 읽고 쓴다. **권한 분리가 안 된다.**
- `@notionhq/notion-mcp-server`의 README에는 더 이상 유지보수하지 않으며 Remote MCP(OAuth)를
  권장한다고 적혀 있다. 동작은 한다. 짧은 프로젝트면 괜찮다고 보되, 사용자에게 사실은 말한다.

## 노션에도 페이지로 남긴다

슬랙 공지만 하면 스크롤에 묻히고, 나중에 합류한 사람은 못 찾는다. 같은 내용을 **홈 아래 페이지**로도
만들어 둔다(「Claude 노션 연결 (선택)」). 팀원 안내 페이지의 '일하는 방식' 끝과 '첫날 전 체크리스트'에서
링크를 걸어 두면 처음 온 사람이 알아서 찾아간다. 체크리스트에는 `(선택)`을 붙인다 — 개발을 모르는 팀원이
필수로 오해하면 첫날부터 막힌다.

**토큰을 그 페이지에 적을지는 사용자에게 묻는다.** 적으면 복사 한 번으로 끝나 편하고, 어차피 그 페이지를
볼 수 있는 사람이 토큰 받을 사람이다. 안 적으면 페이지를 공개하거나 복제해도 토큰이 안 따라간다.
포트폴리오로 노션을 외부에 보여줄 계획이 있으면 그때 그 페이지만 빼면 된다는 것도 같이 말해 준다.
적는 쪽을 고르면 명령어에 토큰을 넣은 채로 써 준다. 복사-붙여넣기 한 번으로 끝나는 게 설치 성공률을 높인다.
