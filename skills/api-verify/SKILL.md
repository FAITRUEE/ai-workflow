# 서버 띄워서 실제 API로 확인

단위 테스트가 통과해도 실제 서버에서는 인증 필터 · 직렬화 · 설정 때문에 다르게 동작한다.
1인 3일 프로젝트(NowWhat)에서 바뀐 것마다 이 순서로 확인했다. 프로젝트마다 아래 칸을 채워
`.claude/skills/api-verify/` 아래에 두면 AI가 매번 같은 방식으로 검증한다.

## 1. 띄운다

- 서버를 **백그라운드로** 띄우고 로그를 파일로 받는다. PID도 파일로 남긴다.
  ```powershell
  Start-Process -FilePath ".\gradlew.bat" -ArgumentList "bootRun","--console=plain" `
    -RedirectStandardOutput "boot.log" -RedirectStandardError "boot.err.log" -NoNewWindow -PassThru |
    ForEach-Object { $_.Id } | Out-File -FilePath "boot.pid" -Encoding ascii
  ```
- 기동 완료 문구(예: `Started …Application in`)가 로그에 뜰 때까지 기다린다. 기다리는 시간을 추측해 적지 않는다.
- DB가 메모리형이면 재시작마다 빈 상태라는 것을 기억한다. 시드 데이터가 필요하면 흐름 안에서 만든다.

## 2. 한 바퀴 돈다 (프로젝트마다 채울 칸)

> 사용자가 실제로 밟는 순서 그대로. 변경과 상관없어 보여도 매번 처음부터.

```
가입 → 로그인(토큰 받기) → 핵심 데이터 2개 이상 만들기 → 목록(정렬 · 점수 확인)
→ 설정 바꾸기 → 목록 다시(값이 바뀌는지) → 상태 바꾸기 → 기록 조회
→ AI 기능 호출(있다면) → 다른 사용자로 남의 데이터 조회(403이어야 함)
```

- **권한 확인을 꼭 넣는다.** 두 번째 사용자로 첫 사용자의 데이터를 조회해 막히는지 본다.
- AI · 외부 호출 기능은 **실제로 호출이 일어나는 조건**인지 확인한다. 후보가 1개뿐이면 호출 없이 대체 동작으로 빠지는 식의 조건이 흔하다.
- 실패 시 대체 동작(폴백)이 있으면 **일부러 실패시켜서**(외부 서버를 끄거나 잘못된 주소로) 대체 동작과 로그를 본다.

## 3. 치운다

- 서버를 종료하고(`taskkill //PID $(cat boot.pid) //T //F`), `boot.log` · `boot.err.log` · `boot.pid`를 지운다. 작업 트리에 남기지 않는다.

## 자주 걸린 함정

- **Windows Git Bash에서 `curl -d '...'`에 한글을 바로 넣으면 깨진다.** 서버는 JSON 해석 실패를 내고,
  오류 경로가 보안 필터에 막히면 400이 아니라 **본문 없는 403**으로 보여 권한 문제처럼 헷갈린다.
  JSON을 파일로 쓰고 `--data-binary @file.json`으로 보낸다.
- 증상(403)과 원인(직렬화 · DB 제약)이 다를 수 있다. **로그와 예외 경로부터** 본다.
- 예외를 삼키는 catch는 로그가 안 남아 대체 동작만 보인다. 원인을 모르면 외부 서버에 직접 요청해 본다.
- 기동 로그의 무해한 경고(예: 기본 보안 비밀번호 생성)는 실제 동작으로 확인한 뒤에만 "무해하다"고 적는다.
