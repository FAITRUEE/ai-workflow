# 청중 눈으로 발표 자료 점검

만든 사람은 모든 숫자와 용어의 뜻을 알지만, 청중은 그 장을 **처음 몇 초** 보고 넘어간다.
이 스킬은 "처음 듣는 사람이 이 장에서 무엇을 가져가나"만 기준으로 본다.

## 점검 기준 — 장마다 이 질문을 던진다

| 기준 | 걸리는 예 | 고치는 방향 |
|---|---|---|
| **숫자에 뜻이 붙었나** | "109/255", "0.471" | 단위 · 무엇의 값인지 · 높은 게 좋은지를 숫자 옆에 |
| **지표 이름이 있나** | "심한 눈부심 점수 0.62" | AUC인지 F1인지 밝힌다 |
| **낮은 숫자가 실패처럼 보이지 않나** | 처음 보는 사진 F1 0.471 | 비교 기준(규칙 · 우연)과 같이 보여 주거나, 뜻이 드러나는 지표를 함께 |
| **그래프가 무엇을 그렸는지 보이나** | 오른쪽 그래프 두 개 | 그래프마다 제목 한 줄 · 축 이름 |
| **용어를 처음 듣는 사람도 아나** | "규칙 세기", "판정 경계" | 쉬운 말로 바꾸거나 첫 등장 때 한 줄 설명 |
| **왜 문제인지 먼저 나오나** | 해결책부터 나옴 | 문제 → 원인 → 해결 순서. 청중이 "그래서?"라고 묻지 않게 |
| **한 장에 한 메시지인가** | 설명 · 표 · 사진이 한 장에 | 장을 나누거나 그림 하나로 |
| **사진이 일을 하나** | 사진은 작고 글이 바깥에 | 사진을 키우고 설명을 사진 위에 직접 |
| **겹치는 장이 없나** | 35쪽과 39쪽이 같은 이야기 | 합치거나 한쪽을 빼기 |
| **앞에 안 나온 말이 갑자기 나오나** | 19쪽에 갑자기 "밝기 규칙" | 처음 나오는 곳에 다리를 놓는다 |

## 대본(스크립트) 기준

- **실제로 소리 내 읽을 문장만.** "(수정)", "→ 여기서 강조" 같은 메모는 뺀다
- 장마다 첫 문장이 그 장의 메시지
- 숫자는 읽기 쉬운 형태로("0.471" → "열 번 중 다섯 번 가까이")
- 30분 발표에 69장이면 장당 약 26초 — 넘치면 표지 · 전환 장을 2~3초로 줄인다

## 순서

1. 전체를 한 번 훑어 **흐름**을 한 줄로 요약해 보여 준다 (요약이 안 되면 그게 첫 번째 문제)
2. 장마다 기준표로 점검 → 고칠 곳을 **쪽 번호 · 무엇이 · 왜 · 어떻게** 로 번호 목록
3. 사용자가 번호를 고르면("2~6번 반영", "3번 빼고") 그것만 고친다
4. 고친 장을 이미지로 렌더링해 겹침 · 넘침 · 흐릿한 글자를 직접 확인한다
5. 대본도 고친 장에 맞춰 같이 고친다
6. 원하면 **예상 질문**을 뽑는다 — 쉬운 질문 5개, 날카로운 질문 5개, 각 질문에 30초 답변

## 하지 않는 것

- 사용자가 고르지 않은 번호 고치기
- 데이터 · 결과 숫자 바꾸기 (표현만 바꾼다)
- 사진 출처를 모르는데 출처 표기를 지어내기 — "출처 확인 필요"로 남긴다
