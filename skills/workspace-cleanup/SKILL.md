# 작업 폴더 정리 — 파일과 문서

AI는 작업하면서 파일을 계속 만든다. 스크린샷, 중간 결과, "혹시 몰라" 만든 사본.
문서도 마찬가지다. 조사 메모, 검토 기록, `_최종`, `_최종2`가 쌓이면 **나도 어느 게 진짜인지 알아보기 어렵다.**
이 스킬은 둘을 같은 원칙으로 정리한다.

## 원칙

1. **먼저 보여 주고, 고른 것만 바꾼다.** 목록이나 계획 없이 지우거나 옮기지 않는다
2. **되돌릴 수 있게.** 지울 땐 휴지통으로, 문서를 합칠 땐 원래 내용이 빠짐없이 들어갔는지 확인한 뒤에
3. **애매하면 그대로 둔다.** 사용자가 직접 만든 파일일 수 있으면 "확인 필요"로 남긴다

---

## ① 필요 없는 파일 치우기

### 찾기 — 지우지 않고 목록만
```bash
python scripts/scan.py <폴더>                    # 정리 후보를 크기순으로
python scripts/scan.py <폴더> --unused-images    # 어디에서도 안 쓰는 그림까지
```

| 분류 | 예 | 기본 판단 |
|---|---|---|
| AI 작업 찌꺼기 | `.playwright-mcp/`, `_workspace/` | 지워도 됨 |
| 캐시 · 빌드 출력 | `__pycache__/`, `node_modules/`, `dist/` | 지워도 됨 (다시 만들 수 있음) |
| 사본 · 이전본 | `_old`, `_v2`, `복사본`, `.bak` | 정본이 따로 있는지 확인 후 |
| 안 쓰는 그림 | 어느 문서 · 스크립트에도 이름이 안 나오는 이미지 | 확인 필요 |
| 열려 있는 파일 | `~$문서.docx` | 건드리지 않음 |

### 치우기
- 사용자가 번호로 고른 것만 휴지통으로
  - Windows: `Microsoft.VisualBasic.FileIO.FileSystem`의 `DeleteFile` · `DeleteDirectory` + `SendToRecycleBin`
  - macOS: `trash`, Linux: `gio trash`
- git이 추적하는 파일은 지우지 않는다 (`git ls-files`로 확인)
- 끝나면 한 줄: **지운 것 N개 · 확보한 용량 · 남겨 둔 것(이유)**

## ② 복잡해진 문서 정리

### 보기 — 무엇이 있는지부터
```bash
python scripts/scan.py <폴더> --docs    # 폴더별 문서 목록 + '버전만 다른 같은 문서' 묶음
```
문서를 열어 보고 하나씩 이렇게 나눈다.

| 나눔 | 뜻 | 어디로 |
|---|---|---|
| **정본** | 지금 기준이 되는 문서 (제출본 · 최신 명세) | 폴더 맨 위에, 버전 표시 없는 이름으로 |
| **근거 · 참고** | 정본을 쓸 때 쓴 조사 · 원문 | `참고/` |
| **지난 기록** | 예전 버전, 끝난 검토 · 점검 결과 | `지난기록/` (지우지 않는다) |
| **합칠 것** | 같은 주제가 여러 파일에 흩어짐 | 정본 하나로 합침 |
| **필요 없음** | 내용이 정본에 다 들어간 초안 | ①처럼 휴지통 후보로 |

### 계획을 먼저 보여 준다
```text
지금                                  →  정리 후
자소서_최종.md, 자소서_최종2.md        →  자소서.md (최종2 내용) + 지난기록/자소서_최종.md
검토_11-19.md, 검토_11-20.md           →  지난기록/
조사.md, 공고_원문.md                  →  참고/
(없음)                                 →  README.md — 이 폴더 안내
```
사용자가 고른 줄만 실행한다.

### 합칠 때
- 두 문서에 **다른 사실**이 있으면 둘 다 남기고, 서로 어긋나면 어느 쪽이 맞는지 묻는다
- 합친 뒤 원래 문서의 문장 · 숫자가 빠짐없이 들어갔는지 대조한다. 빠진 게 없을 때만 원래 문서를 `지난기록/`으로

### 폴더 안내(README.md) 한 장
1. 이 폴더는 무엇을 위한 곳인가 (한 줄)
2. **정본 목록** — 파일 이름 · 무엇인지 · 마지막으로 고친 날
3. 스크립트가 있으면 무엇을 만드는지, 어떤 순서로 돌리는지
4. `참고/` · `지난기록/`에 무엇이 있는지 한 줄씩

### 긴 문서 하나가 복잡할 때
- 맨 위에 **결론 · 현재 상태** 세 줄
- 같은 말을 반복하는 문단은 하나로, 날짜가 지난 "할 일"은 완료 표시 또는 지난 기록으로
- 표로 쓸 수 있는 나열은 표로

## 다시 쌓이지 않게

- 임시 파일은 처음부터 프로젝트 폴더가 아니라 세션 임시 폴더에 만든다
- 고치기 전에 `_v2` · 이전본 사본을 만들지 않는다. 되돌리기는 git이나 원본 생성 스크립트로
- 정본 이름에는 `_최종`, `_v3`을 붙이지 않는다. 버전은 문서 안 변경 이력에
- 큰 작업을 마칠 때 `scan.py`를 한 번 돌리고 남은 것을 알린다

## 하지 않는 것

- 목록 · 계획을 보여 주지 않고 지우거나 옮기기, 영구 삭제
- OneDrive 같은 동기화 폴더 전체를 한 번에 훑기 — 오래 걸린다. 정리할 하위 폴더부터 좁힌다
- `.git/`, `.env`, 키 파일 건드리기
- 문서를 합치면서 내용을 요약해 사실을 빼기
