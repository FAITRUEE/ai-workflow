# OOF 실수 분석

점수가 정체될 때 다음 수는 대개 **틀린 행을 직접 보는 데서** 나온다. 2026-10 분류 대회(양성 F1)에서 이 순서로 v2 → v5 피처를 찾았다: 틀린 행 → 공통점(짝 오류가 정확히 24시간 전, 짝 센서 이탈, 15일 정비 주기) → 피처·규칙.

점수 하나(F1 0.982)만 보면 "튜닝을 더 할까"로 흐르기 쉽다. 같은 점수라도 실수가 어느 기간·어느 종류 행에 몰렸는지에 따라 할 일이 완전히 다르다 — 데이터 시작 구간(이력 없음)에 몰리면 test 와 무관하고, 특정 조건 행에 몰리면 피처 하나로 풀린다.

## 순서

1. **나눠 세기** — `scripts/analyze.py` 로 run 마다 전체·구간별 F1, 잘못 판정(FP), 놓침(FN)을 표로. 구간은 시간 fold(예: 3개월 단위)와 "데이터 시작 구간 제외"를 꼭 같이 본다. test 가 train 다음 기간이면 시작 구간 실수는 test 에 없는 실수일 수 있다.
2. **이론상 최대치 확인** — 어떤 피처로도 못 맞힐 행(예: 첫날 이상 시각 고장)이 있으면 그걸 빼고 계산한 최대 F1 을 먼저 말한다. "0.982 → 남은 여지 10여 행"처럼 남은 몫을 행 수로 말하면 판단이 쉬워진다.
3. **틀린 행 보기** — 놓침·잘못 판정 행을 피처와 함께 출력(`--show-errors`, `--cols`). 비슷하지만 맞힌 행과 나란히 비교해 차이를 찾는다. 작은 결정나무(depth 3~4)를 "애매한 행 집합"에 맞추면 갈리는 기준이 바로 보인다.
4. **피처 묶음 빼보기** — 원래 값만 / +이력 / +오류 / 전체처럼 묶음을 더해 가며 F1 이 어디서 뛰는지 본다. 점수의 출처를 사용자에게 설명할 때 가장 설득력 있다.
5. **규칙과 비교** — 찾은 패턴을 학습 없는 규칙으로도 만들어 F1 을 잰다. 규칙이 모델과 같거나 낫다면 모델이 그 조합을 못 배우고 있다는 뜻 → 규칙을 피처로 넣는다. 기준값을 넓게 바꿔도 test 판정 수가 그대로인지 확인해 train 에 과하게 맞춘 게 아님을 보인다.
6. **test 판정 차이 행** — 두 제출의 0/1 을 비교해(`--test-csv`) 다른 행만 뽑고, 그 행의 원본 기록(같은 기계 앞뒤 며칠)을 본다. "누가 맞을지"를 데이터 구조로 설명할 수 있어야 제출을 고를 수 있다.
7. **백테스트로 비공개 구간 추정** — 기간별 F1 과 "틀림 0/n 이면 95% 상한 3/n"(rule of three)으로 남은 구간 예상 범위를 말한다. 공개 점수가 일부만 채점할 때 특히 필요.

## 흔한 함정

- `from common import *` 로 모듈 전역(예: fold 그룹)을 가져오면 load() 전 값이 복사됨 → `common.X` 로 읽기
- 06시만 학습하는 식으로 행을 줄인 run 은 나머지 예측이 0 → 전체 행 순위·상관은 동점투성이라 의미 없음. 예측이 0 아닌 행만으로 비교
- test 확률을 fold 수로 나눌 때 실제 fold 수를 쓰는지 (설정값 N_FOLDS 와 시간 fold 수가 다를 수 있음)
- 기준값은 OOF 에서 찾되, 섞은 결과는 섞은 OOF 로 다시 찾는다. test 를 test 안에서 순위 매기면 train 양성 비율이 강제돼 판정 수가 틀어짐

## 보고 방식

사용자는 쉬운 말과 표를 선호한다. 결과는 "맞힘/놓침/잘못 판정 행 수" 표로, 발견은 "무엇이 → 왜 → 그래서 무엇을"로. 코드 변수명 대신 무엇을 뜻하는지로 쓴다 (예: `hrs_since_error1` → "마지막 error1 이후 지난 시간").

## 스크립트

`scripts/analyze.py` — numpy·pandas 만 필요.

```
python analyze.py --y y.npy --oof runs/A/oof.npy runs/B/oof.npy \
    --groups groups.npy [--exclude-mask warmup.npy] \
    [--show-errors --features X.pkl --cols col1,col2] \
    [--test-csv sub_A.csv sub_B.csv]
```

- `--y`: 0/1 정답 (npy, 또는 `file.csv:컬럼`)
- `--oof`: 확률 OOF 여러 개 (이름은 상위 폴더명)
- `--thr`: 기준값 (없으면 run 마다 F1 최대 기준값을 찾음)
- `--groups`: 구간 라벨 배열 (시간 fold 번호 등)
- `--exclude-mask`: True 인 행을 뺀 점수도 같이 (데이터 시작 구간 등)
- `--show-errors`: 첫 run 의 틀린 행을 `--features` 표의 `--cols` 와 함께 출력
- `--test-csv`: 제출 CSV 2개 이상 → 판정 수와 서로 다른 행 id

y·groups·features 는 프로젝트의 로더로 한 번 저장해 두고 쓴다 (예: `np.save('y.npy', y)`, `X.to_pickle('X.pkl')`).
